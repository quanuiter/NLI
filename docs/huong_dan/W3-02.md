# W3-02 – Thiết lập fine-tune PhoBERT (B – Quân)

**Mục tiêu:** notebook fine-tune `vinai/phobert-base` cho bài toán cặp câu chạy được trên Colab, đã chạy thử trên 1.000 mẫu.
Code dùng chung cho mọi lần chạy PhoBERT (W3-03, W4-01–03) và XLM-R (W4-04).

**File:** `src/transformer.py` (dùng chung cho M4 và M5), `scripts/run_transformer.py`, `notebooks/05_phobert.ipynb`.

## Kiến thức cần nắm
- **Fine-tune:** lấy mô hình đã được huấn luyện trước trên văn bản tiếng Việt (PhoBERT), thêm một lớp phân loại 3 nhãn lên trên,
  rồi huấn luyện tiếp toàn bộ mô hình trên dữ liệu NLI.
- **Đầu vào cặp câu:** tokenizer tự ghép `<s> premise </s></s> hypothesis </s>`. PhoBERT đọc hai câu cùng lúc
  (self-attention giữa mọi token của hai câu). Đây là khác biệt lớn nhất so với M2, M3, vốn mã hóa từng câu riêng rồi mới so sánh.
- **Bắt buộc dùng bản đã tách từ:** PhoBERT được huấn luyện trước trên văn bản đã tách từ bằng VnCoreNLP
  (chi tiết trong `data/manual/ghi_chu_tach_tu.md`). XLM-R thì dùng văn bản thô.

## Đã chuẩn bị sẵn
- **Chọn `max_len` = 256** dựa trên độ dài token của cặp câu (`results/analysis/token_lengths.json`):
  PhoBERT có 99% cặp câu dài dưới 105 token, chỉ 17/100.000 cặp XNLI train dài hơn 256 (dài nhất 381).
  Mỗi batch chỉ đệm tới cặp dài nhất trong batch, nên `max_len` lớn không làm chậm.
- **Hai cấu hình** (`transformer.CONFIGS`), sẽ so trên dev ở W3-03:
  - A: lr 2e-5, batch 32, 3 epoch, dropout 0,1;
  - B (theo bài ViANLI, mục 6.2): lr 1e-5, batch 16, 7 epoch, dropout 0,4.
  Cả hai: weight decay 0,01, warmup 10% số bước, fp16 khi có GPU, đánh giá dev mỗi epoch, giữ checkpoint có macro-F1 dev cao nhất.
- **Đã chạy thử trên CPU** (vài chục mẫu) cho cả PhoBERT và XLM-R: huấn luyện, chọn epoch tốt nhất, lưu checkpoint,
  lưu kết quả qua `evaluate_and_save` đều chạy được.

## Các bước (trên Colab)
1. Mở `notebooks/05_phobert.ipynb` từ link Colab, bật GPU: **Runtime → Change runtime type → T4 GPU**.
2. Chạy ô 0, rồi ô **Kiểm tra GPU và dữ liệu đã tách từ**. Nếu thiếu file tách từ thì chạy ô `segment_data.py`.
3. Chạy ô **chạy thử** (`--smoke`): 1.000 mẫu train, 200 dev, 200 mẫu mỗi tập test, 1 epoch. Kết quả vào `results/smoke/`.
4. Chạy ô in kết quả chạy thử.

## Tự kiểm tra
- Không lỗi, `thiết bị: cuda`, `fp16: True`, có kết quả `vianli_test` và `vinli_test` với n = 200.
- Ghi lại thời gian huấn luyện để ước lượng thời gian chạy thật (ViANLI 8.012 cặp, XNLI 100.000 cặp).
- GPU hết bộ nhớ (CUDA out of memory): giảm `batch_size` trong `CONFIGS`.
