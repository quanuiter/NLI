# W3-07 – Review code chéo (cả hai)

**Mục tiêu:** phát hiện lỗi trước khi chốt số liệu. Quan trọng hơn là **cả hai đều hiểu toàn bộ code**,
vì khi bảo vệ thầy hỏi ai thì người đó phải trả lời được.

## Phân công
- **M (Quang) review code của t:** `src/data.py`, `src/evaluate.py`, `src/m2.py`, `src/m3.py`.
- **T review code của m:** `notebooks/01_eda.ipynb`, `notebooks/02_m1.ipynb`.

## Các bước
1. Trên GitHub: tab **Commits** → bấm vào commit cần xem → rê chuột vào dòng code → bấm dấu **+** để viết bình luận.
2. Đi theo danh sách kiểm tra bên dưới. Chỗ nào chưa ổn hoặc chưa hiểu thì viết bình luận hỏi.
3. Người viết code sửa lại hoặc giải thích.

## Danh sách kiểm tra
- [ ] Dữ liệu chỉ lấy qua `load_scenario` / `load_split`, không tự đọc file riêng.
- [ ] **Không dùng tập test để chọn siêu tham số.** Mọi lần thử cấu hình chỉ dựa trên `d['dev']`.
- [ ] **Không dùng cột `id` làm đặc trưng** (`id` của ViANLI chứa mã nhãn).
- [ ] Có `set_seed(...)` trước khi huấn luyện, chạy lại ra đúng kết quả cũ.
- [ ] Kết quả lưu bằng `evaluate_and_save`, `config` ghi đủ các siêu tham số đã dùng.
- [ ] Mọi số liệu trong báo cáo đều có file tương ứng trong `results/`.
- [ ] Người review **giải thích lại được** từng hàm chính bằng lời của mình (nói thử cho người kia nghe).
